# Устройства и умения

## Как устроена связка

Каждое устройство в модуле — это набор **умений** (capabilities/properties Яндекса). Каждое умение привязано к паре **объект → свойство** MajorDoMo:

- Яндекс присылает команду «включить» → модуль вызывает `setGlobal('Kitchen.Light.status', 1)`;
- MajorDoMo меняет состояние → при запросе `query` модуль читает `getGlobal('Kitchen.Light.status')` и отдаёт его Яндексу;
- если включён reportable, модуль сам отправляет новое значение в Яндекс.

Одно устройство может использовать разные объекты и свойства для разных умений. Например, яркость — `Kitchen.Light.brightness`, цвет — `Kitchen.Light.color`.

## Добавление устройства

1. Нажмите **Добавить устройство**.
2. Укажите название, тип и помещение. Название и тип обязательны.
3. Добавьте хотя бы одно умение.
4. Для каждого умения выберите объект и свойство.
5. Сохраните устройство.

После сохранения модуль пересобирает discovery-конфиг и, если настроены callbacks, отправляет его в Яндекс.

## Типы устройств

Тип определяет иконку и допустимые умения. Каталог покрывает основные категории:

- освещение: люстра, лампа, лента, бра, торшер, диммируемый свет;
- электрика: розетка, выключатель, реле;
- климат: термостат, кондиционер, обогреватель, увлажнитель, очиститель, вентиляция;
- медиа: телевизор, приставка, ресивер, камера;
- техника: кофеварка, чайник, мультиварка, холодильник, стиральная и посудомоечная машины, утюг, пылесос;
- открывание и доступ: шлагбаум, шторы, замок, домофон, клапан;
- датчики: движения, вибрации, освещённости, открытия, климата, протечки, кнопки, газа, дыма;
- счётчики: холодной и горячей воды, электричества, газа, тепла;
- питомцы: поилка, кормушка;
- другое.

## Основные умения

| Умение | Тип значения | Пример свойства | Примечание |
| --- | --- | --- | --- |
| `on` | 1/0 | `Kitchen.Light.status` | Включить/выключить. |
| `brightness` | 1–100 | `Kitchen.Light.brightness` | Диапазон можно изменить (Min/Max/Step). |
| `temperature` | °C | `Living.Thermostat.target` | Целевая температура. |
| `thermostat` | режим | `Living.Thermostat.mode` | `auto`, `heat`, `cool`, `eco`, `dry`, `fan_only`. |
| `volume` | 1–100 | `Living.TV.volume` | Громкость. |
| `channel` | номер | `Living.TV.channel` | ТВ-канал. |
| `rgb` | hex | `Kitchen.Light.color` | Цвет в формате `RRGGBB`. |
| `temperature_k` | кельвины | `Kitchen.Light.temp` | Цветовая температура. |
| `open` | 0–100 | `Living.Curtains.position` | Степень открытия. |
| `get_stream` | URL | `Domofon.streamUrl` | HLS-поток камеры. |
| `*_sensor` | число/событие | `Kitchen.Temperature.value` | Датчики и счётчики. |

Полный список — в редакторе устройства: он сгруппирован по capability (`on_off`, `toggle`, `range`, `mode`, `color_setting`, `video_stream`, `float`, `event`).

## Преобразование значений

Значения в MajorDoMo и Яндексе могут не совпадать. Для этого в каждом умении есть **соответствие значений**:

| Пресет | Что делает |
| --- | --- |
| Без преобразования | Передаёт значение как есть. |
| `1/0 → on/off` | Для `on` и похожих переключателей. |
| `1/0 → opened/closed` | Для датчиков открытия. |
| `1/0 → detected/not_detected` | Для движения, дыма, газа. |
| `1/0 → leak/dry` | Для протечки. |
| `0/1/2 → empty/low/normal` | Для уровня корма и воды. |
| `1/2/3 → click/double_click/long_press` | Для кнопок. |
| Пользовательский | Своя таблица «значение MajorDoMo → значение Яндекс». |

Для датчика открытия модуль учитывает свойство `ncno` объекта: если оно равно `nc`, значения `opened`/`closed` инвертируются.

## Диапазоны и Split

- **Min/Max/Step** доступны для умений типа `range`. Если свойство хранит проценты, оставьте `1–100` и шаг `1`.
- **Split** доступен для `on_off`: вместо одной кнопки Яндекс покажет отдельные «Включить» и «Выключить». Split несовместим с reportable для этого умения.

## Reportable

Reportable отправляет изменение свойства в Яндекс сразу после `setGlobal()`. Требуется токен Яндекс Диалогов и ID навыка в настройках модуля. Если credentials не заданы, переключатель в карточке устройства не показывается, а конфиг устройства содержит `reportable=false`.

## Удаление устройства

При удалении устройства модуль снимает все привязки `addLinkedProperty` и отправляет discovery-callback. Свойства объектов и их значения не удаляются.
