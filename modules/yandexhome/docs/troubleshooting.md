# Диагностика проблем

## Сначала включите журнал

В настройках модуля включите **Отладка DebMes**. Записи пишутся в `cms/debmes/yandexhome.log` (путь зависит от настроек проекта). Там видны входящие запросы, ответы callbacks и изменения свойств.

Если нужно видеть ping-запросы Яндекса, включите **Логировать ping**.

## Навык не связывается

| Симптом | Что проверить |
| --- | --- |
| Яндекс показывает ошибку авторизации | `authorize.php` и `token.php` открываются снаружи по HTTPS без basic auth; OAuth2 ID/KEY совпадают с консолью. |
| Страница авторизации не открывается | Reverse proxy требует логин/пароль или закрывает `/modules/`. |
| «Неверный логин или пароль» | Логин и пароль в настройках модуля; регистр важен. |
| После ввода пароля снова форма | Сессия не сохраняется: проверьте cookie и `session.save_path` PHP. |
| `invalid_client` в token.php | KEY не совпадает с сохранённым в `yandexhome_oauth`; сохраните настройки ещё раз. |

## Устройства не появляются в приложении

1. У устройства есть хотя бы одно умение с привязкой к объекту и свойству.
2. Тип устройства выбран из каталога.
3. Нажмите **Обновить список устройств** в приложении Яндекс.
4. В настройках модуля нажмите **Проверить callback** — если HTTP не 2xx, проверьте токен и ID навыка.

Discovery пропускает устройство, если `buildDeviceConfig()` вернул пустую строку: нет `id`, `name`, `type`, `status_info` или ни одного умения.

## Алиса не управляет устройством

- Проверьте, что свойство объекта существует и доступно для записи.
- Включён ли **Автономный режим**? При нём запись запрещена.
- Срабатывает ли `setGlobal()` вручную из X-Ray?
- Совпадает ли `instance` умения с тем, что присылает Яндекс. Журнал покажет `Capabilities type ... instance ...`.
- Для `rgb` свойство должно принимать hex (`RRGGBB`), для `on` — `1`/`0`.
- Для штор и клапанов проверьте соответствие `opened`/`closed` и свойство `ncno` объекта.

## Reportable не работает

- В настройках заданы **Токен Яндекс Диалогов** и **ID навыка**.
- У умения включён **Reportable**, а не только привязка.
- Для `on` с **Split** reportable отключается принудительно.
- Нажмите **Проверить callback**: HTTP 401/403 — проблема токена, 404 — неверный ID навыка.

## Ошибки базы данных

Модуль использует таблицы `yandexhome_devices` и `yandexhome_oauth`. Если после обновления страница пустая, проверьте, что модуль установлен: `cms/modules_installed/yandexhome.installed`. Откройте `/panel/yandexhome.html` — модуль создаст таблицы сам.

Пересобрать `CONFIG` устройств можно кнопкой **Пересобрать CONFIG** в настройках. Это не меняет привязки и значения свойств.

## Сброс интеграции

- **Сбросить OAuth** удаляет токены. Пользователям придётся заново объединить аккаунты.
- **Удалить фейки** убирает служебные устройства `[YH_FAKE]`.
- Полное удаление модуля снимает привязки свойств и удаляет таблицы.

## Полезные команды

```bash
# Проверить синтаксис PHP-файлов модуля
php -l modules/yandexhome/yandexhome.class.php

# Посмотреть журнал модуля (путь может отличаться)
tail -n 100 cms/debmes/yandexhome.log
```
